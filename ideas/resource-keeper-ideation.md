# 개인 자료 수집·회상 도우미 — 아이디에이션

> "나중에 봐야지" 하고 저장한 링크·이미지·글을 한곳에 모으고, AI가 내용을 파악해 자동 분류하고,
> 필요할 때(또는 잊어버릴 때쯤) 다시 꺼내주는 개인용 세컨드 브레인.

---

## 1. 아이디어 평가: 만들 가치가 있는가?

**결론부터: 있다. 다만 "저장 앱"이 아니라 "다시 보게 만드는 앱"으로 만들어야 한다.**

- 이 문제는 실재하고 보편적이다. 북마크·저장 기능을 쓰는 사람의 대다수가 저장한 것을 다시 열지 않는다.
  Pocket이 2025년에 서비스를 종료한 이유도 결국 "저장은 쉬운데 소비가 안 되는" 구조를 못 풀었기 때문이다.
- 기존 서비스(Raindrop, mymind, Notion 클리퍼, 네이버 Keep, 카톡 "나에게 보내기")는 전부
  **수집·정리까지만** 해준다. 진짜 병목인 **회상(resurface)** — "생각날 때쯤 다시 알려주기" — 를
  해주는 서비스는 거의 없다. 여기가 이 아이디어의 차별점이다.
- 특히 한국 사용자 맥락(네이버 카페, 인스타그램)은 로그인 장벽 때문에 글로벌 서비스가 잘 못
  다루는 영역이라, 개인용으로 직접 만들 실익이 크다.

핵심 명제: **저장의 가치는 저장하는 순간이 아니라 다시 꺼내 보는 순간에 생긴다.**
모든 기능 우선순위를 이 기준으로 정한다.

---

## 2. 문제 정의

| 단계 | 현재 상태 | 문제 |
|---|---|---|
| 수집 | 카톡 나에게 보내기, 인스타 저장, 카페 북마크, 스크린샷 | 저장처가 흩어져 있고, 저장 시점엔 내용 정리가 안 됨 |
| 이해 | 없음 | 제목만 보고는 뭘 저장했는지 기억 안 남. 스크린샷은 검색도 안 됨 |
| 회수 | 없음 | 다시 볼 계기가 없음. 찾으려 해도 어디 저장했는지 모름 |

→ 세 단계를 하나의 파이프라인으로 잇는 것이 제품의 본질.

## 3. 핵심 컨셉: 수집 → 이해 → 회수

### 3-1. 수집 (Capture) — 마찰 최소화가 전부

저장이 3초 이상 걸리면 안 쓰게 된다. 입력 채널은 "이미 쓰는 앱" 안에 있어야 한다.

- **메신저 봇이 최적의 시작점.** 텔레그램 봇(또는 카카오톡 채널)에 링크/이미지/텍스트를
  그냥 던지면 끝. 앱 설치·로그인 불필요, 모바일 공유 시트에서 바로 전송 가능.
- 이후 확장: 모바일 공유 익스텐션(clozet에서 React Native 경험 있으니 가능), 웹 클리퍼.

입력 형태별 처리:

| 입력 | 처리 방법 | 비고 |
|---|---|---|
| 일반 링크 | 본문 크롤링 → LLM 요약 | 블로그, 뉴스 등은 쉬움 |
| **네이버 카페 링크** | 로그인 장벽으로 크롤링 어려움 → **스크린샷을 같이 보내는 UX로 우회** | 링크는 "원본 바로가기"용으로만 보관 |
| **인스타그램 링크** | 동일. oEmbed로 캡션 일부는 가능하나 불안정 | 릴스는 스크린샷 + 사용자 한줄 메모 유도 |
| 이미지/스크린샷 | 비전 모델(Claude)로 OCR + 내용 해석 | 스크린샷이 사실상 만능 입력 |
| 텍스트 | 바로 요약·태깅 | 가장 쉬움 |

**설계 포인트: 링크를 "열 수 있는 것"으로 기대하지 말 것.** 폐쇄 플랫폼 대응은 크롤링 군비경쟁
대신 "스크린샷 우선" 전략으로 푼다. 스크린샷은 어떤 앱이든 통하고, 비전 모델이 다 읽어준다.

### 3-2. 이해 (Understand) — 저장 즉시 AI 파이프라인

자료 하나가 들어오면 자동으로:

1. **본문 추출**: 크롤링 또는 이미지 OCR/해석
2. **요약**: 3줄 요약 + "왜 저장했을 법한지" 한 줄 (예: "○○ 레시피 — 재료 목록 포함")
3. **태깅·분류**: LLM이 태그 3~5개 부여. 카테고리는 고정 목록 강제가 아니라
   **자료가 쌓이면서 자동으로 형성** (임베딩 클러스터링 → "요리", "육아", "투자", "인테리어" 식으로 이름 붙임)
4. **임베딩 저장**: 나중에 의미 기반 검색·연관 자료 연결용
5. 저장 직후 봇이 요약 카드를 회신 → "제대로 이해했는지" 즉시 확인 가능, 이게 신뢰를 만든다

### 3-3. 회수 (Resurface) — 이 제품의 존재 이유

세 가지 방식을 조합:

1. **검색 (수동 회수)**: "저번에 저장한 이유식 레시피" 같은 자연어 질문 → 시맨틱 검색으로 답.
   봇에게 물어보면 요약 + 원본 링크를 돌려줌.
2. **주기적 다이제스트 (수동적 회수)**: 주 1회 "이번 주 저장한 것 + 3주 전 저장하고 안 본 것 2개"
   메일/메시지. 이미 ETF 봇에서 GitHub Actions + SMTP 메일 인프라를 운영 중이라 그대로 재활용 가능.
3. **맥락 리마인드 (능동 회수, 차별화 킬러 기능)**:
   - 시점 기반: 저장 시 "3주 뒤 다시 보여줘" 지정, 또는 간격 반복(1주→1달→3달)
   - 내용 기반: 자료에서 시의성 추출 (예: "5월 가정의 달 행사" 글 → 4월 말에 알림,
     "이유식 6개월 차" 글 → 해당 시기에 알림)
   - 연관 기반: 새 자료 저장 시 "예전에 저장한 이것과 관련 있어요" 연결

**주의: 알림 피로가 최대 리스크.** 리마인드는 기본 주 1~2회 상한, 다이제스트에 묶어서 보내고,
"다시 안 보기" 피드백으로 학습하게 한다. 알림이 스팸이 되는 순간 앱은 죽는다.

## 4. MVP 제안

거창한 앱 대신 **"텔레그램 봇 + Claude API + SQLite + GitHub Actions 주간 다이제스트"** 4주 분량:

```
[텔레그램 봇]
  ├─ 링크/이미지/텍스트 수신
  ├─ Claude API: 본문 추출·요약·태깅 (이미지는 비전으로 해석)
  ├─ SQLite + 임베딩 저장 (자료 수천 건까지는 이걸로 충분)
  ├─ "/찾아줘 <질문>" → 시맨틱 검색 응답
  └─ [GitHub Actions cron] 주간 다이제스트 (기존 ETF 봇 메일 인프라 재활용)
```

- 서버는 무료 티어(Fly.io/Railway) 또는 집 PC로 충분. 개인용이라 비용은 Claude API 호출료 정도
  (자료 1건당 수십 원 수준, Haiku 모델로 낮출 수 있음).
- 카카오톡 채널 봇도 가능하지만 심사·설정이 무거우므로 MVP는 텔레그램으로 검증 후 이전 판단.

### 단계별 로드맵

| 단계 | 내용 | 검증할 가설 |
|---|---|---|
| **P0 (MVP)** | 봇 수집 + AI 요약·태깅 + 검색 + 주간 다이제스트 | "저장한 걸 실제로 다시 보게 되는가" |
| **P1** | 자동 카테고리 클러스터링, 시점 리마인드, 웹 뷰(모아보기) | 리마인드 빈도의 적정선 |
| **P2** | 맥락·연관 리마인드, 모바일 공유 익스텐션(RN) | 능동 회수가 정말 유용한가 |
| **P3** | (선택) 타인과 공유, 멀티유저 서비스화 | 남들도 돈 낼 문제인가 |

## 5. 리스크와 대응

| 리스크 | 심각도 | 대응 |
|---|---|---|
| 인스타/네이버카페 크롤링 차단 | 높음 | 스크린샷 우선 전략으로 원천 회피. 크롤링은 되면 좋고 안 되면 그만인 부가 기능으로 |
| 알림 피로 → 앱 방치 | 높음 | 다이제스트로 묶기, 주 1~2회 상한, 피드백 학습 |
| 저작권 | 낮음 | 개인 소장·백업 용도는 문제 없음. 공유 기능(P3)을 넣을 때만 재검토 |
| AI 비용 | 낮음 | 개인용 볼륨이면 월 수천 원 이하. 요약은 Haiku급으로 충분 |
| 만들다 지침 (개인 프로젝트 공통 리스크) | 중간 | P0를 4주 안에 끊고 **내가 매주 다이제스트를 실제로 여는지**만 본다 |

## 6. 성공 지표 (개인용 기준)

- 주간 다이제스트 오픈율 — 내가 실제로 여는가
- 저장 후 7일 내 "다시 본" 자료 비율 (기존 습관에서는 사실상 0%)
- 검색으로 원하는 자료를 찾은 성공률
- 주간 저장 건수가 유지되는가 (수집 마찰이 낮다는 증거)
